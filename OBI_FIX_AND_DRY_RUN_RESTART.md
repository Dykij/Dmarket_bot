## Раздел 1: Список изменений

### obi.py — Новые функции

| Функция | Формула | Описание |
|---------|---------|----------|
| `normalized_obi()` | `(bid-ask)/(bid+ask)` | Нормализованный OBI в [-1,1], не зависит от цены |
| `ofi()` | `OBI_current - OBI_previous` | Изменение OBI между циклами (моментум) |
| `obi_z_score()` | `(current-mean)/std` | Z-score относительно истории предмета |

### demand_strategy.py — Улучшения v17.3

| # | Улучшение | Было | Стало |
|---|-----------|------|-------|
| 1 | Нормализованный OBI | `simple_obi()` (volume-weighted) | `normalized_obi()` (price-independent) |
| 2 | OFI сигнал | Нет | `ofi(current, previous)` — моментум |
| 3 | Z-score калибровка | Фиксированные пороги | `obi_z_score()` с fallback |
| 4 | OBI как risk-gate | Только BUY/SELL сигнал | Блокирует при OBI < -0.3 |
| 5 | OFI как primary signal | Нет | Штраф 50% если OFI < -0.1 |
| 6 | Порог ликвидности | min_volume из thresholds | min 5 ордеров (жёсткий) |
| 7 | EWMA сглаживание | Нет | alpha=0.3 на OBI |
| 8 | Кэш истории | Нет | 20 наблюдений на предмет |
| 9 | Логирование | Только demand_ratio | + OBI, OFI, Z-score |

## Раздел 4: Почему проблемы не были обнаружены ранее

### Проблема с API ключами

**Почему не видна в локальных тестах:** Локальные тесты использовали ключи из `.env`, которые действительны. GitHub Secrets содержали устаревшие ключи (установлены 2026-07-23). Это инфраструктурная проблема, не связанная с кодом.

**Урок:** Всегда проверять, что GitHub Secrets синхронизированы с `.env` перед запуском CI/CD.

### Проблемы с OBI

**Почему не видны в симуляции:**
1. Симуляция с балансом $250 использовала подмену данных, не реальные DMarket API
2. Формула `simple_obi()` работала на синтетических данных, но на реальных данных проявились недостатки:
   - Шум при малых bid/ask count
   - Отсутствие калибровки по истории
   - Нет персистентности сигнала (одиночный "миг" книги)

**Урок:** Стратегия должна тестироваться на реальных данных минимум 24 часа перед запуском марафона.

### Отсутствие backtest

**Рекомендация:** После 2 недель работы собрать статистику OBI/OFI/Z-score и провести ретроспективный анализ. Это позволит:
1. Подтвердить или скорректировать пороги
2. Определить оптимальный alpha для EWMA
3. Калибровать Z-score порог для каждого ценового сегмента
