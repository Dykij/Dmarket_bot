# Microstructure Analysis Subsystem — Subsystem Knowledge

## Архитектура и Роли
Папка `src/analysis/microstructure/` содержит чистые математические модели для анализа микроструктуры рынка (анализ стакана заявок, микро-трендов, волатильности). Это критически важный пакет для работы `target_sniping`.

**Компоненты:**
- `obi.py` — расчет Order Book Imbalance (дисбаланса стакана). Позволяет предсказывать краткосрочные движения цены на основе перевеса покупателей/продавцов.
- `volatility.py` — расчет исторической и подразумеваемой волатильности (micro-volatility, tick-level volatility).
- `volume.py` — анализ объемов торгов (Volume Profile, VWAP, анализ аномальных всплесков).
- `signals.py` — генератор торговых сигналов (комбинирует OBI, объемы и волатильность в конкретные триггеры Buy/Sell).
- `__init__.py` — оркестратор пакета, реэкспортирующий функции для внешнего использования.

## Зависимости (Cross-Module)
*Связи подтверждены через RAW-grep и archy.*

**Входящие вызовы (Кто использует `microstructure`):**
- **Главный фасад:** `src/analysis/microstructure.py`
- **Trading Core (`src/core/target_sniping`):** Пакет глубоко интегрирован в торговый пайплайн. Вызывается из:
  - `microstructure_pipeline.py` (основной потребитель)
  - `cycle_orchestrator.py`
  - `demand_strategy.py`
  - `resale.py` & `resale_prod.py`
  - `validations.py`, `ranking.py`

**Исходящие вызовы:**
- Пакет является **листовым (leaf) модулем** в дереве зависимостей.
- `__init__.py` делает внутренние импорты из `obi`, `signals`, `volatility`, `volume`.
- Сами модули расчетов не зависят от остального кода `src.*` — они работают исключительно с DataFrame и числовыми массивами.

## Правила для агентов
- **Strictly pure functions:** Модули в этой папке не должны делать сетевых запросов или читать базу данных. Все данные (снимки стакана, тики) передаются в функции как аргументы.
- **Производительность:** Это критический путь. Не использовать медленные циклы `for` в Python; все расчеты должны быть векторизованы (через `pandas` / `numpy` / `numba`).
- Любые изменения в `obi.py` или `signals.py` требуют обязательного прогона на `backtester` перед деплоем, так как они напрямую меняют логику покупок бота.
