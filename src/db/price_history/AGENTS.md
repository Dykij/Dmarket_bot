# DB Price History Subsystem — Subsystem Knowledge

## Архитектура и Роли
Папка `src/db/price_history/` (несмотря на название) содержит логику работы со всей локальной базой данных бота (SQLite/PostgreSQL). 

**Ядро БД:**
- `core.py` — центральный класс `PriceDB`, инициализация пула соединений (через `asyncpg` или `aiosqlite`), миграции и создание всех таблиц. Импортирует все остальные модули.
- `__init__.py` — реэкспорт `price_db` (глобальный инстанс БД).

**Таблицы и Репозитории (Data Access Layer):**
- `history.py` — история цен на предметы (используется для оценки трендов и средних цен).
- `inventory.py` — кэш инвентаря бота, предметы на продаже.
- `targets.py` — цели снайпинга (что мы хотим купить).
- `pump_blacklist.py` — черный список предметов, которые подозреваются в пампе.
- `asset_status.py` — статус конкретных активов (в процессе покупки, продажи и т.д.).
- `analytics_logs.py` — логи для аналитики и подсчета профита.
- `low_fee.py` — предметы с пониженной комиссией.
- `state.py` — персистентное состояние бота.

## Зависимости (Cross-Module)
*Связи подтверждены через RAW-grep и archy.*

**Входящие вызовы (Кто использует `price_history`):**
Модуль используется практически повсеместно во всём проекте, так как `price_db` — это основной способ персистентного хранения.
- `src/core/target_sniping/` (почти все файлы).
- `src/core/` (`resale_pipeline.py`, `autonomous_scanner.py`, `item_intel.py`, `daily_briefing.py`).
- `src/risk/` (`risk_manager.py`, `circuit_breaker_manager.py`, `liquidity_manager.py`).
- `src/analytics/` (`event_calendar.py`, `self_reflection.py`).
- `src/telegram/control_bot/` (`callbacks.py`, `resilience.py` и др.).
- `src/telegram_reporter.py`, `src/utils/charts.py`.
- `src/inventory_manager.py`.

**Исходящие вызовы (От чего зависит `price_history`):**
- **DB Core:** `src.db.db_retry` (декоратор `with_db_retry` используется во всех файлах для устойчивости к локам SQLite/сбоям сети).
- *Внутренняя структура (archy):* `core.py` и `__init__.py` централизуют доступ, импортируя все остальные файлы-репозитории. Сами репозитории независимы друг от друга.

## Правила для агентов
- **Не использовать глобальные транзакции на долгие процессы:** Запросы к БД должны быть короткими.
- **Обязательно использовать `with_db_retry`:** Любой метод, делающий запрос к БД, должен быть обернут в декоратор `with_db_retry` для обработки `OperationalError` (особенно важно при использовании SQLite в WAL-режиме под нагрузкой).
- При добавлении новой таблицы обязательно добавить её создание в `core.py`.
