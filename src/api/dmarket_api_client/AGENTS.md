# DMarket API Client — Subsystem Knowledge

## Documentation Source of Truth
- **Архитектура:** Обязательно ознакомьтесь с `docs/ARCHITECTURE.md` для понимания потока данных.
- **Актуальная спецификация:** `https://docs.dmarket.com/v1/swagger.html`
  (HTML/Redoc, `__redoc_state`, версия API v2.0.0)
- **НЕ использовать:** ранее скачанный `swagger.json` — неполон,
  содержит устаревшие пути, НЕ включает v2-эндпоинты.
- Машиночитаемый JSON-spec для v2 публично не доступен (проверено
  2026-08-23). При необходимости парсить HTML Redoc.

## Rate Limits (из документации v2.0.0)
- **Sign-in:** 20 RPM
- **Fee / Market items:** 2 RPS
- **Остальные эндпоинты:** 6 RPS (неавторизованные)
- **Авторизованные:** лимиты приходят в заголовках ответа
  (`X-RateLimit-Remaining`, `X-RateLimit-Reset`) — клиент их
  **не читает и не использует**. Известный техдолг.

## Известный техдолг
1. **429-обработка:** Клиент делает экспоненциальный retry на 429,
   но НЕ читает `Retry-After` заголовок (исправлено частично,
   но заголовки ответа всё ещё не парсятся).
2. **Cloudflare HTML:** При Cloudflare-challenge API может вернуть
   HTML вместо JSON. Клиент попытается `json()` → crash.
   Нужен content-type guard.
3. **`/exchange/v1/transactions`:** Используется в коде, но
   отсутствует в документации. Может сломаться без предупреждения.

## Правила для агентов
- Все P&L-расчёты **обязаны** использовать `fee_utils.get_sell_fee_rate()`,
  а не `Config.FEE_RATE` напрямую.
- При добавлении нового эндпоинта — сверить с Redoc (не со старым JSON).
- При изменении retry/backoff логики — проверить соответствие rate limits
  таблице выше.
