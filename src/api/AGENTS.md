# API Subsystem — Subsystem Knowledge

## Архитектура и Роли
Папка `src/api/` является корневой для логики работы с внешними интерфейсами, но, помимо папки-клиента (`dmarket_api_client`), содержит набор независимых утилит для парсинга и обработки данных, приходящих от API.

**Утилиты и Парсеры:**
- `dmarket_parser.py` — парсер ответов DMarket (на базе Pydantic и `orjson` для ускорения). Осуществляет валидацию и нормализацию приходящих JSON (может дублировать функционал Rust-парсера в зависимости от контекста).
- `fair_price_calculator.py` — расчет справедливой цены (Fair Price) предмета на основе предложений (офферов) и истории.
- `candle_builder.py` — агрегация сырых трейдов в свечи (OHLCV) для графиков и аналитики.
- `health.py` — эндпоинты проверки состояния API/бота.
- `exceptions.py` — локальные исключения API-уровня.

*(Взаимодействие непосредственно с DMarket описано в `dmarket_api_client/AGENTS.md`).*

## Зависимости (Cross-Module)
*Связи подтверждены через RAW-grep и archy.*

**Входящие вызовы (Кто использует файлы `src/api/*.py`):**
- **Target Sniping:** `src/core/target_sniping/filter.py` (вероятно, использует `dmarket_parser` или `fair_price`).
- **DMarket Client:** `src/api/dmarket_api_client/market.py`.

**Исходящие вызовы:**
- Файлы верхнего уровня полностью независимы от остального `src.*` кода. Они импортируют только внешние библиотеки (`orjson`, `pydantic`, `structlog`).
- *Внутренняя структура (archy):* В корне папки файлы не связаны друг с другом (отсутствуют внутренние `edges`). Каждый скрипт — изолированная утилита.

## Правила для агентов
- Парсинг ответов: если требуется высокая производительность для парсинга (hot-path), проверьте, нужно ли использовать `dmarket_parser.py` или Rust-модуль.
- Все изменения в расчетах в `fair_price_calculator.py` должны покрываться юнит-тестами, так как от них напрямую зависит прибыльность снайпинга.
