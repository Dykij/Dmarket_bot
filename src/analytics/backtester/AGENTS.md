# Backtester Subsystem — Subsystem Knowledge

## Архитектура и Роли
Папка `src/analytics/backtester/` содержит изолированный движок для тестирования торговых стратегий на исторических данных. Это "песочница", в которой можно прогнать алгоритм снайпинга/ресейла без риска реальными деньгами. Пакет не имеет исходящих зависимостей на `src.*` и работает как независимая библиотека.

**Ядро движка:**
- `engine.py` — основной класс бэктестера. Имитирует торги (покупка/продажа), учитывает комиссии и трекает P&L в виртуальном времени.
- `walk_forward.py` — реализация метода Walk-Forward Optimization (перекрестная проверка на скользящем окне для поиска устойчивых параметров стратегии).
- `__init__.py` — реэкспорт.

**Компоненты тестирования:**
- `strategies.py` — базовые классы и реализации тестируемых стратегий.
- `models.py` — Pydantic-модели и дата-классы, описывающие виртуальные ордера, сделки, портфель.
- `metrics.py` — расчет итоговых метрик (Sharpe Ratio, Max Drawdown, Win Rate, ROI).

## Зависимости (Cross-Module)
*Связи подтверждены через RAW-grep и archy.*

**Входящие вызовы (Кто использует `backtester`):**
- **Главный фасад:** `src/analytics/backtester.py` (реэкспортирует этот пакет для использования в скриптах аналитики).
- В основной торговой цепочке демона (в `target_sniping`) бэктестер напрямую **не используется**. Он вызывается отдельными скриптами в CLI или Jupyter Notebooks для валидации идей перед их интеграцией в `core.py`.

**Исходящие вызовы (От чего зависит `backtester`):**
- Пакет **полностью независим**. Нет импортов внешних модулей из `src.*`. Все исторические данные передаются в `engine.py` через параметры (DataFrame или списки объектов).
- *Внутренняя структура (archy):* `walk_forward.py` выступает высокоуровневым оркестратором, вызывая `engine.py`, `models` и `strategies`. `engine.py` прогоняет `strategies` и генерирует результаты через `metrics.py`. Фундаментом служат структуры из `models.py`.

## Правила для агентов
- **Full Isolation:** Бэктестер никогда не должен обращаться к реальной базе данных или реальному API.
- **Pure Functions / Determinism:** При одних и тех же входных исторических данных, движок всегда должен выдавать идентичные метрики. Не использовать случайности без фиксированного seed.
