# Historical Data Subsystem — Subsystem Knowledge

## Архитектура и Роли
Папка `src/analytics/historical_data/` содержит изолированную логику для скачивания, хранения и агрегации исторических данных по ценам CS2-предметов. Эти данные используются исключительно для аналитики и бэктестинга, не влияя напрямую на горячий торговый контур (в котором данные берутся из живой БД `src.db.price_history`).

**Компоненты:**
- `collector.py` — основной класс-сборщик. Запускает задачи на скачивание истории для списков предметов.
- `sources.py` — классы-коннекторы к источникам данных (например, агрегация данных из сторонних API CS2-прайсинга, если таковые подключены).
- `models.py` — Pydantic-модели и дата-классы для описания исторических баров (свечей) и точек данных.
- `__init__.py` — реэкспорт.

## Зависимости (Cross-Module)
*Связи подтверждены через RAW-grep и archy.*

**Входящие вызовы (Кто использует `historical_data`):**
- **Backtester:** `src/analytics/backtester/engine.py` и `strategies.py` (используют эти модели и коллектор для получения данных перед прогоном тестов).
- **Главный фасад:** `src/analytics/historical_data.py`.

**Исходящие вызовы:**
- Пакет является **полностью независимым** от остального кода `src.*`. Все нужные библиотеки импортируются глобально.
- *Внутренняя структура (archy):* `collector.py` использует `sources` для стягивания данных и сериализует их в структуры из `models`. `sources` также зависит от `models`.

## Правила для агентов
- **Rate Limiting:** Модули `sources` и `collector` должны реализовывать строгий Rate Limiting (лимиты запросов) при вытягивании истории со сторонних API.
- Пакет не должен импортировать классы из `src.db.price_history`. Его зона ответственности — внешние исторические данные для бэктестов, а не боевая БД снайпера.
