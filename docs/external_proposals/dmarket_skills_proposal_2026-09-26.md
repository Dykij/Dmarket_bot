## Версия 1 — исходный список скиллов

Для интеграции ИИ в Antigravity IDE в качестве инструмента разработки
Dmarket_bot, набор скиллов должен быть сфокусирован на валидации данных,
генерации моков, тестировании API DMarket и расчёте метрик. Это изолирует
модель от принятия торговых решений, делая её помощником для написания и
отладки Rust/Python кода.

Стакан (Order Book) в торговле скинами CS2 на DMarket состоит из Asks
(офферы/предложения) — уникальных предметов с флоатами, паттернами и
трейд-локами, и Bids (таргеты) — заявок на покупку предмета с определённым
названием и опциональными фильтрами.

### 1. Скиллы для работы со структурой стакана (Market Depth & Offers)

- **dmarket_fetch_orderbook_schema** — ИИ запрашивает актуальную JSON-схему
  ответов DMarket для эндпоинтов офферов и market items, чтобы генерировать
  Pydantic/Serde-модели без галлюцинаций в названиях полей.
- **mock_orderbook_generator** — генерирует синтетические срезы стакана по
  заданным параметрам (например: "50 офферов AK-47 Redline FT, 3 предмета с
  флоатом < 0.16, 2 с трейд-локом 8 дней") для unit-тестов сортировки и
  поиска арбитражных окон без реальных запросов к API.
- **parse_cs2_attributes** — валидирует специфичные атрибуты предмета из
  сырого объекта DMarket (float value, paint index/seed, наклейки,
  Souvenir/StatTrak) для правильного извлечения ценности предмета в коде.

### 2. Скиллы для работы с ордерами (Targets / Bids)

- **validate_target_payload** — анализирует JSON payload перед отправкой на
  создание таргета: обязательные поля (Amount, Price, Title), корректность
  форматирования фильтров (float_min/float_max).
- **calculate_target_metrics** — принимает цену покупки, ожидаемую цену
  продажи и комиссию DMarket, помогает писать математическое ядро
  (ROI, спред, скрытые комиссии при отмене ордеров).
- **simulate_target_matching** — эмулирует логику матчинга DMarket: на вход
  подаётся созданный таргет и тестовый стакан, на выходе — какие предметы
  будут выкуплены; помогает тестировать частичное исполнение (Partial Fill).

### 3. Инфраструктурные и защитные скиллы (API & Security)

- **ed25519_signature_validator** — берёт тело запроса ордера и тестовые
  ключи, генерирует/проверяет подпись `X-Request-Sign`, помогает отлаживать
  аутентификацию при ошибках 401.
- **rate_limit_analyzer** — информирует о жёстких лимитах DMarket (частота
  запросов стакана, выставление/снятие таргетов в секунду), помогает
  проектировать асинхронные воркеры с экспоненциальной задержкой.

**Интеграция:** реализуется как MCP-серверы или системные промпты с
JSON-схемами API DMarket; кастомные команды (`@dmarket_validate_target`),
которые ИИ вызывает, передавая написанный код, получая в ответ подтверждение
правильности структуры стакана или подписи.

## Версия 2 — обновлённый список (по официальной документации Dmarket Trading API v2.0.0)

### 1. Скиллы анализа стакана (Market Depth & Order Book Skills)

- **dmarket_get_aggregated_prices** — быстрый срез стакана: лучшие цены
  спроса/предложения и их количество. Входные параметры: `limit`, `cursor`,
  `filter.game` (`a8db` для CS2), `filter.titles[]`. Ожидаемые данные:
  массив `aggregatedPrices` с полями `orderBestPrice`, `orderCount`,
  `offerBestPrice`, `offerCount`.
- **dmarket_find_targets_by_title** — чтение активных ордеров конкурентов.
  Входные параметры: `game_id`, `title`. Ожидаемые данные: массив `orders`
  с полями `amount`, `price` (в центах), `attributes` (`phase`,
  `floatPartValue`). Роль ИИ: построение стен ликвидности и оценки
  конкуренции по ценовым уровням/паттернам/флоатам.
- **dmarket_get_item_sales_history** — данные о последних закрытых сделках
  (до 12 месяцев) на самой платформе, без обращения к внешним источникам
  цены. Роль ИИ: статистическая фильтрация выбросов и расчёт медианной цены
  для безопасного выставления собственных Targets.

### 2. Скиллы управления ордерами (Target Management & Auth)

- **dmarket_ed25519_request_signer** — формирование заголовков `X-Api-Key`,
  `X-Sign-Date`, `X-Request-Sign` (`dmar ed25519 <подпись>`). Строка для
  подписи: (HTTP Method) + (Route path + query params) + (body string) +
  (timestamp). Роль ИИ: надёжный HTTP-мидлвар (Rust `ed25519-dalek`/NaCl или
  Python `PyNaCl`) для автоматической подписи приватных запросов.
- **dmarket_create_targets** — выставление новых заявок на покупку
  (`GameID` = `a8db` для CS2). Роль ИИ: формирование JSON-пейлоада, retry-
  логика при 400/429.
- **dmarket_remove_targets** — снятие ордеров (для изменения цены DMarket
  требует удалить старый ордер и создать новый). Роль ИИ: логика
  репрайсинга через цикл remove→create с минимизацией сетевой задержки.

### 3. Скиллы мониторинга состояния (State & Event Skills)

- **dmarket_get_user_targets** — проверка статуса собственных ордеров.
  Входные параметры: `gameId` (обязательно), `title`, `treeFilters`,
  `limit`, `cursor`. Ожидаемые данные: `targetId`, `status`, `priceCents`,
  `amount`, `attributes`. Роль ИИ: сличение `priceCents` с лучшими ценами
  конкурентов, сигнал, если ордер перебит.
- **dmarket_get_account_balance** — расчёт баланса и риск-менеджмент.
  Ожидаемые данные: `usd`, `usdAvailableToWithdraw`, `dmc`. Роль ИИ:
  валидация достаточности средств перед генерацией новых ордеров.

### Обновлённый системный промпт

> "Ты — инженер-разработчик. Твоя единственная зона ответственности:
> кодогенерация, рефакторинг и написание unit-тестов для алгоритмического
> Dmarket_bot на Python и Rust. Ты не принимаешь торговых решений.
> Твоя архитектура строго ограничена Dmarket Trading API (v2.0.0). При работе
> с API ты обязан реализовывать Ed25519 NaCl подписи заголовков `X-Api-Key`,
> `X-Sign-Date` и `X-Request-Sign` согласно официальной спецификации
> маркетплейса.
> Доступные контракты, на которые ты должен опираться при написании
> HTTP-клиентов и структур данных: получение среза спреда (aggregated
> prices), парсинг стен ликвидности конкурентов (targets-by-title),
> инвентаризация активных `targetId` (`user/targets`), выставление и
> перестановка ордеров (create/remove targets), парсинг баланса `usd` в
> модуле риск-менеджмента (account balance), построение скользящих средних
> цен по истории закрытых ордеров.
> При написании логики ценообразования категорически запрещено ссылаться на
> любые источники данных, кроме официального DMarket Trading API. Используй
> исключительно расчёт спреда и исторические данные закрытых ордеров (Closed
> Targets) платформы DMarket. Весь код должен быть асинхронным, безопасным и
> обрабатывать rate limits платформы."
